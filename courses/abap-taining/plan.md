# ABAP研修 対話型レッスン制作プラン

新卒コンサルタント（IT初学者）向けに、SAPにおけるABAP開発を「業務 → システム → ABAP」の3層で理解させる、対話型スライドショー教材を制作するための実装計画。

---

## 0. 制作の前提（必読ルール）

- 教材は `template/lesson-template.html` を**コピー**して作る、自己完結型の `.html`（1レッスン＝1ファイル）。
- `<head>` / `<style>` / トップバー / コントロール / `<script>` は**絶対に編集しない**。`{{PLACEHOLDER}}` の置換と `.slide` セクションの増減のみ。
- 1スライド＝1概念＝`<section class="slide" data-title="…">`。`data-title` は必ず設定（ジャンプメニュー表示名）。
- 各レッスンは **5〜12スライド**、必ず**1つ以上のMermaid図**と**最後にクイズ1〜3問**を含む。
- 使える部品は **callout（tip/warning/note）/ コードブロック / Mermaid図 / quiz** のみ。新しいCSSや色は追加しない。
- 文章は日本語・初学者向け・例示重視。専門用語には必ずやさしい言い換えを添える。
- 作成後は `index.html`（`template/index-template.html` からルートに1回コピー）にレッスンリンクを追加する。

---

## 1. 対話型ペダゴジーを既存部品にどう載せるか

このテンプレには「会話吹き出し」専用部品が無いため、登場人物を**既存のcalloutで色分け**して表現する（新CSS禁止のため）。各レッスンで凡例スライドは作らず、自然に運用する。

- 先生の説明・問いかけ → `callout note`（青）。冒頭に「先生：」を付ける。
- Aくん（理系・規則/数式で納得）向け補足や反応 → `callout tip`（緑）。冒頭に「Aくん：」。
- Bちゃん（文系・PC苦手・生活の比喩が有効）向け補足や反応 → `callout warning`（橙）。冒頭に「Bちゃん：」。
- 「よくあるつまずき」→ `callout warning`。冒頭に「つまずき：」。

各トピックは要件の10項目（ひとことで言うと／たとえ話／業務の意味／システムの動き／ABAP対応／誤解しやすい点／Aくん補足／Bちゃん補足／確認質問／ミニ演習＋優しいフォロー）を、スライド本文・callout・クイズに割り付ける。

## 3. 全レッスン共通のスライド構成（型）

各レッスンは原則この並びで 6〜9 スライドにする。

1. **Overview**（テンプレ既定の1枚目）：タイトル、1行サマリ、メタ（⏱所要時間/📶レベル/🏷トラック）、「この章のゴール」2〜4個。
2. **まずは身近な例**：たとえ話を `callout note`（先生）で導入。
3. **SAP業務ではこう見える**：業務上の意味。会計知識は最小限。
4. **システムとして何をしているか**：必要なら本文＋小さなMermaid図。
5. **ABABではこう表す**：コードブロックで最小例。構文暗記でなく「なぜ必要か」を本文で。
6. **図解スライド**（Mermaid必須）：処理の流れ／関係を1枚で。
7. **Aくん／Bちゃんの理解ポイント＆つまずき**：tip / warning calloutで対比。
8. **確認質問＋ミニ演習**：先生の問い → 模範的な対話例 → 優しいフォロー例（note/tip/warning）。
9. **クイズ**（必須・最後）：1〜3問。`data-answer` は0始まり、`data-explanation` 必須。フィードバックは `Quiz` コンポーネントが表示。各スライド末尾相当に「今日のひとこと（不安軽減メッセージ）」を入れる。

「この章で出てくるABAPキーワード」は、ABAP対応スライドかクイズ直前に `callout tip` でまとめる（暗記でなく位置づけ確認用）。

## 4. レッスン別アウトライン

### 00-introduction.html — なぜABABを学ぶのか
- **ゴール**：追加開発の必要性／「業務要件をシステムの動きに翻訳する」見方／不安の解消。
- スライド：導入会話 → パッケージ導入でも追加開発が要る場面 → 翻訳という見方の図解 → A/Bの最初のつまずき予想 → クイズ。
- 図（mindmap or flowchart）：依頼書(業務) → 仕様(システム) → 指示書(ABAP)。
- キーワード：`REPORT` `PARAMETERS` `SELECT` `WRITE`（名前だけ紹介）。

### 01-overview.html — 研修全体マップ
- **ゴール**：全体の流れと「最終的に作れるもの」を先に提示。
- スライド：研修マップ（演習1〜4 仕訳日記帳／5〜6 会計伝票登録／7 適切なプログラミング）→ 画面入力→取得→加工→出力→DL/登録のパイプライン図 → 照会と登録の違い予告 → クイズ。
- 図（flowchart LR）：入力 → 取得 → 加工 → 出力 → 登録。

### 02-business-basics.html — 仕訳日記帳と会計伝票
- **ゴール**：仕訳日記帳＝動きの記録一覧／会計伝票＝1件の正式記録、を比喩で理解。
- スライド：家計簿の比喩 → ヘッダと明細 → 登録と照会の流れ → 外部ファイル取込とは → クイズ。
- 図（flowchart）：外部ファイル → チェック → 変換 → 登録 → 結果。

### 03-abap-minimum-unit.html — はじめてのレポートプログラム
- **ゴール**：レポートプログラムとは／変数・定数・コメントの意味。
- スライド：作成→実行→結果を見る流れ → 変数（Aくん:記号／Bちゃん:入力欄）→ 定数 → コメントの理由 → クイズ。
- コード例：`REPORT` `DATA` `CONSTANTS` とコメント行。

### 04-selection-screen.html — 入力を受け取る
- **ゴール**：選択画面＝検索フォーム／`PARAMETERS` と `SELECT-OPTIONS` の違い。
- スライド：検索フォームの比喩 → 単一指定 vs 範囲指定 → 入力が後続SELECT条件になる流れ → クイズ。
- 図（flowchart）：入力値 → WHERE条件 → 取得対象の絞り込み。

### 05-internal-tables.html — データを扱う基本
- **ゴール**：内部テーブル＝行の集まり／作業領域＝今触る1行。
- スライド：棚と1枚の比喩 → 1件の箱 vs 複数件の表 → `SORT`/`LOOP`/`READ TABLE` → Excelとの異同 → つまずき（DBではない／型そのものではない）→ クイズ。

### 06-select-from-db.html — データベースから取得する
- **ゴール**：`SELECT` が何をしているか／取得可否の判定。
- スライド：倉庫から取り出す比喩 → BKPF/BSEG/T001/T003T を「どんな情報の表か」粒度で → ヘッダと明細 → `SY-SUBRC` と `IF`/`CASE`/`MESSAGE` → クイズ（取れた/取れないの判定箇所）。
- 図（erDiagram 簡易 or flowchart）：条件 → 抽出 → 件数判定 → 分岐。

### 07-output-report.html — 出力をつくる
- **ゴール**：帳票＝整えて見せる／抽出だけでは不十分。
- スライド：見にくい議事録の比喩 → `WRITE`/`ULINE`/`SKIP`/`NEW-LINE`/`NEW-PAGE` → 見やすさはユーザー価値 → クイズ。

### 08-combine-data.html — 複数データをまとめる（演習2相当）
- **ゴール**：ヘッダ＋明細を合わせて出力／後で使いやすい形に整える。
- スライド：領収書を整理する比喩 → 複数内部テーブルの使い分け → `MOVE`/`MOVE-CORRESPONDING`/`APPEND`/`CLEAR`/`REFRESH` → クイズ。
- 図（flowchart）：取得 → 対応付け → 整形 → 蓄積。

### 09-control-flow.html — 制御の考え方（対話厚め・図解前提）
- **ゴール**：サプレス処理／`AT FIRST`・`AT LAST`・`AT NEW`・`AT END OF`／フラグ。
- スライド：同じ見出しを繰り返さない比喩 → 制御ブロックの図解 → フラグとは → `SY-SUBRC` だけでは足りない場面 → 多重ネストを避ける → クイズ。
- 図（flowchart）：キー変化点での分岐。**このレッスンは対話calloutを多めに。**

### 10-modularization.html — プログラムを分かりやすくする
- **ゴール**：サブルーチンで処理を分ける理由／`USING`・`CHANGING`／変数スコープ／GUI・イベント・DL処理の意味。
- スライド：手順書を章分けする比喩 → なぜ分けるか → `FORM`/`PERFORM` と引数 → グローバル vs ローカル → 機能追加で整理が要る体感 → クイズ。
- 図（flowchart）：メイン → 各サブルーチン呼び出し。

### 11-document-posting.html — 会計伝票登録へ進む
- **ゴール**：照会と登録の責任差／外部ファイル→登録→履歴→結果／アドオンテーブル・汎用モジュール・BAPI・ロックオブジェクト。
- スライド：閲覧メモ vs 正式台帳の比喩 → 登録フロー図 → BAPIはなぜ必要か → ロックは何を守るか → 「見る」と「登録する」の整理 → クイズ。
- 図（sequenceDiagram）：取込 → 検証 → ロック → 登録 → コミット → 履歴 → 結果。

### 12-real-world.html — 実務っぽい観点
- **ゴール**：追加要望時の見方／設計・実装・テストのつなぎ方／コメント・命名・履歴・単体テストの意味。
- スライド：増改築に図面が要る比喩 → 仕様変更時に最初に見る3点 → 影響分析→修正→回帰の循環 → 「動けば良い」ではない → クイズ。
- 図（flowchart）：仕様差分 → 影響分析 → 修正 → テスト。

### 13-good-programming.html — 適切なプログラミング（演習7相当）
- **ゴール**：パフォーマンスと保守性／10年後も使う視点／悪い例・良い例の対比。
- スライド：渋滞する近道の比喩 → なぜ `SELECT`/`LOOP` の書き方で差が出るか → 悪い例 vs 良い例（コードブロック2つを会話で対比）→ コメント・履歴・開発標準 → 引き継げる書き方 → クイズ。
- 図（flowchart）：無駄なDBアクセス/重複ループ → 削減後。

```html
    <small>· 初学者 · 15分</small></li>
```

## 6. 制作順序（推奨）

1. `index.html` をルートに用意（トラックの枠だけ先に作る）。
2. `00`〜`03` を作成（導入〜最小単位）。各作成後に `index.html` へ追記。
3. `04`〜`10` を作成（仕訳日記帳の演習群：入力〜分割）。
4. `11`〜`13` を作成（会計伝票登録〜適切なプログラミング）。
5. 各レッスンで §8 チェックリストを自己検証（ブラウザ単体で開き、Next/Prev・ジャンプメニュー・クイズ動作を確認）。

---

## 7. 品質基準（各レッスン共通）

- 「業務 → システム → ABAP」の順序を崩さない。先にコードを書かない。
- 1スライド1メッセージ。密度が高ければ2枚に割る。
- 専門用語は必ずやさしい言い換え併記（例：サプレス＝同じ表示を繰り返さないこと）。
- つまずきやすい順に補足を厚く（特に：入力条件設計＝章4、内部テーブル概念＝章5、登録の責任差＝章11、制御＝章9）。
- 受講者が「自分でもついていけそう」と思える優しいトーンを全体で一貫させる。
