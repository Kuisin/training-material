# ゼロから完全理解！ERPの全体像と「SAP S/4HANA」徹底解剖コース

## 第1章：なぜ世界中の大企業は「ERP」を導入するのか？（ビジネスの課題と解決）

- ERP誕生の歴史と目的
- 各部門（営業、工場、経理）が個別のシステムを持つことの限界（データのサイロ化）
- バケツリレー業務の廃止：二重入力、確認待ち、請求漏れはなぜ起きるのか？
- **Single Source of Truth（単一の真実の情報源）**の思想
  - 企業内のあらゆる「モノ」と「カネ」の動きを、1つの巨大なデータベースに統合する意味
- 経営層の視点：1ヶ月待たないと分からなかった「全社の利益」を、今この瞬間リアルタイムで把握する価値

## 第2章：SAP S/4HANAの進化と「HANAデータベース」の技術的特異性

### SAPの歴史

- メインフレーム時代から、クライアント/サーバー型（R/3）、そして S/4HANA への進化

### HANAデータベースの革新（インメモリ × カラム型）

- **インメモリコンピューティング** — ディスク I/O のボトルネックを排除し、すべてを RAM 上で処理する圧倒的な速度
- **カラム型（列指向）とロー型（行指向）の違い** — 従来の RDBMS（PostgreSQL など）の構造と比較した、集計処理における HANA の優位性
- **HTAP の実現** — トランザクション（OLTP）とデータ分析（OLAP）を、別々のデータベースに分けずに 1 箇所で同時に処理する仕組み

### Universal Journal（ユニバーサルジャーナル）

- 過去何千個もあったテーブル群を「1つの巨大な明細テーブル（ACDOCA）」に統合した、究極のデータモデルのシンプル化

## 第3章：業務を網羅するコアモジュールと「データ連動」の仕組み

### ロジスティクス領域（モノの動き）

- **SD（販売管理）** — 見積、受注、出荷、請求までのプロセス
- **MM（在庫購買管理）** — 発注、入庫、請求書照合と、在庫の評価
- **PP（生産管理）** — BOM（部品表）やルーティング（作業手順）に基づく生産計画（MRP）と実績管理

### ファイナンス領域（カネの動き）

- **FI（財務会計）** — 外部の株主や税務署へ報告するための B/S（貸借対照表）・P/L（損益計算書）の作成
- **CO（管理会計）** — 内部の経営判断のための製品原価計算、部門別採算マネジメント

### 【最重要】完全統合の心臓部：「自動仕訳」のメカニズム

- 工場で原材料を消費した（モノが動いた）瞬間に、裏側で「材料費」として会計伝票（カネの動き）が寸分の狂いもなく自動生成される仕組み

## 第4章：全体最適か、個別最適か？（SaaSエコシステムとのアーキテクチャ比較）

### Best of Breed（特化型 SaaS 群）のメリットと限界

- 個別の優秀な SaaS（営業管理、人事、会計）を API でつなぐアプローチの弱点（連携時のレイテンシ、トランザクションエラー時のロールバックの難しさ）

### S/4HANA によるグローバルガバナンス

- 世界中の子会社で「マスタデータ（顧客、品目など）」と「業務プロセス」を強制統一するアプローチ
- 多言語・多通貨・複数法人のデータを一元管理する堅牢性

## 第5章：ERP導入・移行プロジェクトの実態とデータ移行

### スクラッチ開発の罠と「Fit to Standard」

- 自社独自のやり方にシステムを合わせる（アドオン開発）ことによる技術的負債の蓄積
- 世界の優良企業のベストプラクティス（標準機能）に、自社の業務プロセスを合わせるアプローチ

### マイグレーション（システム移行）の戦略

- **Greenfield（新規導入）** と **Brownfield（既存 SAP からのコンバージョン）** の違い
- **データマイグレーションの壁** — レガシーシステム（数万件の旧データ）からのデータクレンジングと、新システムへの正確な流し込み（ETL プロセス）の重要性

## 第6章：モダンな拡張開発と次世代アーキテクチャ（クリーンコア戦略）

### Clean Core（クリーンコア）思想の台頭

- バージョンアップを妨げる「ERP 本体の直接改造（レガシーな ABAP 開発）」の禁止

### SAP BTP（Business Technology Platform）による外部拡張

- ERP 本体の外側（クラウドプラットフォーム上）で独自の追加機能を開発し、API 経由で ERP と連携させるモダンな開発手法
- Java や Node.js を活用した「SAP Cloud SDK」による、エンタープライズ規模の拡張アプリケーション開発

## 第7章：稼働後の世界とデータの高度利用

### SAP Fiori による UI の進化

- 複雑な入力画面から、ユーザーの役割（ロール）に基づいた直感的な Web/モバイルインターフェースへの移行

### Embedded Analytics（組み込み分析）

- 別途 BI ツール（データウェアハウス）にデータを移すことなく、基幹システムの画面上でリアルタイムに数億件の明細から予実分析を行う仕組み
