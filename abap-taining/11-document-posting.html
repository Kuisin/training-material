会計伝票登録へ進む

「見る」から「書き込む」へ。登録の責任の重さと、安全に登録する仕組みを学びます。

⏱ 30分📶 初学者🏷 ABAP研修

この章で学ぶこと

  • 照会（見る）と登録（書き込む）の責任の違い
  • 外部ファイル → 検証 → 登録 → 履歴 → 結果、という登録フロー
  • 登録を支える部品：アドオンテーブル・汎用モジュール・BAPI・ロックオブジェクト

閲覧メモ と 正式な台帳

これまでは「台帳を見るだけ（照会）」でした。これからは「台帳に正式に書き込む（登録）」をします。書き込みは、間違えると正式記録が汚れるので、より慎重さが必要です。

先生：見るのは何度やっても安全。でも書き込みは“消えない記録”を残します。だから検証やロックといった守りの仕組みが必要になります。
Bちゃん：下書きと、清書（提出する書類）の違いみたいですね。清書は緊張します。

図で見る：登録の一連の流れ

sequenceDiagram
  participant F as 外部ファイル
  participant P as ABAPプログラム
  participant S as SAP(伝票)
  F->>P: 取込（データを読む）
  P->>P: 検証（ルールチェック）
  P->>S: ロック（他から触らせない）
  P->>S: 登録（BAPIで伝票作成）
  S-->>P: 結果（伝票番号 or エラー）
  P->>S: コミット（確定）
  P->>P: 履歴・結果を記録/表示

BAPI ＝ SAP公式の「安全な登録窓口」

伝票テーブルに直接書き込むのは危険です（整合性が崩れる）。BAPI は、SAPが用意した「正しい手順で登録してくれる公式の窓口」。これを通せば、必要なチェックや関連更新もまとめて面倒を見てくれます。

つまずき：「テーブルに直接 INSERT すればいい」は厳禁。会計伝票は必ず BAPI など正式な手段で登録します。
Aくん：APIを通すことで、内部の整合性ルールを破らずに済むんですね。

ロック ＝ 「使用中」の札

2人が同時に同じデータを書き込むと、記録が壊れます。ロックオブジェクトは、トイレの「使用中」札のように「今このデータは私が触っています」と示し、二重更新を防ぎます。

Bちゃん：試着室の「使用中」札と同じですね。空くまで待つ。
先生：登録のような“書き込み”では、ロックで守ってから処理するのが基本です。終わったら必ず解放します。

登録を支える部品（位置づけ）

  • アドオンテーブル：標準にない情報を保存する“自社用の追加の表”（取込履歴など）
  • 汎用モジュール：部品化された処理のまとまり（FORMの強力版・他からも呼べる）
  • BAPI：SAP公式の業務処理窓口（伝票登録など）
  • ロックオブジェクト：同時更新を防ぐ「使用中」札
この章のABAPキーワード：BAPI / ロックオブジェクト / 汎用モジュール / アドオンテーブル / コミット。

照会と登録、責任の違いを整理

Aくん：照会は読み取りだけ＝安全。登録は書き込み＝整合性・排他・確定（コミット）まで責任を持つ、という違いですね。
Bちゃん：見るのは気軽、書くのは責任重大。心構えから違うんですね。
先生：その通り。だから登録処理は「検証 → ロック → BAPI → コミット → 結果記録」という型を守ります。怖がる必要はなく、型どおりに進めれば大丈夫です。
