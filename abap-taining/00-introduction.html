なぜABAPを学ぶのか

「業務のお願いごと」を「システムの動き」に翻訳する仕事 — それがABAP開発です。

⏱ 15分📶 初学者🏷 ABAP研修

この章で学ぶこと

  • SAPという完成品を入れても、なぜ「追加の開発」が必要になるのか
  • ABAPは「業務の言葉」を「コンピュータの言葉」に翻訳する仕事だ、という見方
  • プログラミング未経験でも大丈夫、という気持ちの土台づくり

まずは、3人の登場人物から

このレッスンには3人が出てきます。先生と、新卒2人です。あなたに近いほうの言葉を、特に拾ってください。

先生：これから一緒にABAP（エービーアップ）を学びます。SAP（サップ）という会計システムを、会社ごとの事情に合わせて手直しするための言語です。怖がらなくて大丈夫ですよ。
Aくん：プログラミングは少しかじりました。理屈で納得したいタイプです。
Bちゃん：パソコンは得意じゃなくて…。例え話があると安心します。

完成品の家でも、リフォームはする

SAPは「すでに建っている立派な家」のようなものです。たいていの部屋（機能）は最初から揃っています。でも、住む人によって「ここに棚が欲しい」「この動線を変えたい」が出てきます。

先生：SAPは世界中の会社で使えるよう、広く作られています。でも「うちの会社のこのやり方」までは、最初から入っていません。そこを足すのがABAP開発です。
つまずき：「パッケージ＝買えば終わり」と思いがちですが、実際は“自社に合わせる作業”がほぼ必ず発生します。

こんなとき、追加開発が登場する

たとえば会計の現場では、こんな依頼がよく来ます。どれも「標準のSAPだけでは足りない」場面です。

  • 他システムから来た取引ファイルを、まとめてSAPに取り込みたい
  • 自社の見やすい形で、取引の一覧（帳票）を出したい
  • 登録前に「うちのルール」で自動チェックしたい
Aくん：標準にない処理を“足す”ためのプログラム、ということですね。

ABAP開発＝「翻訳」の仕事

本レッスン全体を貫く合言葉は「業務 → システム → ABAP」です。人のお願いを、機械が分かる手順に直していきます。

先生：いきなりコードを書くのではありません。まず「何をしたいか（業務）」を聞き、「システムでどう実現するか」を考え、最後に「ABAPでこう書く」へ降りていきます。この順番を絶対に崩しません。

図で見る「翻訳」の流れ

依頼書（業務の言葉）が、仕様（システムの言葉）を経て、指示書（ABAPの言葉）になります。

  C --> D["動く機能"]
Bちゃん：左から右へ、だんだん細かくしていくんですね。料理のレシピに近いかも。

これから出てくる言葉（名前だけ）

今は意味を覚えなくて大丈夫です。「こういう名前が出てくるんだな」とだけ知っておいてください。

この研修で出てくるABAPキーワード（位置づけ確認用）
  • REPORT … プログラムの始まりを宣言する合図
  • PARAMETERS … 利用者に値を入力してもらう欄
  • SELECT … データベースから情報を取り出す
  • WRITE … 画面に結果を書き出す
先生：丸暗記は不要です。「なぜ必要か」を理解すれば、書き方は後からついてきます。

最初につまずきやすいところ

Aくん：理屈は分かるけど、SAP特有の用語（伝票、テーブル名…）が多くて道に迷いそう。→ 用語は出るたびに“やさしい言い換え”を付けるので大丈夫。
Bちゃん：英語のコードを見ると固まってしまう。→ コードは「指示文」。英単語の意味（select＝選ぶ など）で読めば怖くありません。
先生：分からないのは「あなたの理解力」ではなく「まだ習っていないだけ」。順番に積めば必ず追いつけます。
