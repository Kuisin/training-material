データベースから取得する

SELECT が何をしているのか。取れたか・取れなかったかをどう判定するのかを学びます。

⏱ 25分📶 初学者🏷 ABAP研修

この章で学ぶこと

  • SELECT ＝ データベースという倉庫から条件に合うデータを取り出すこと
  • 会計でよく使う表（BKPF / BSEG / T001 / T003T）が何の情報か
  • 取得に成功したか（SY-SUBRC）を見て処理を分ける考え方

SELECT ＝ 倉庫から必要な箱を取り出す

データベースは、たくさんの箱（データ）が整理された巨大な倉庫です。SELECT は倉庫番に「この条件の箱だけ持ってきて」とお願いする命令です。

先生：倉庫の中身を全部出すと大変です。だから前章の「入力＝条件」が効いてきます。条件で絞って、必要な箱だけ取り出します。
Bちゃん：図書館で読みたい本だけ借りる、みたいな感じですね。

会計でよく出る表（ざっくり）

細かい列名は今は不要。「どんな情報の表か」だけ掴めば十分です。

  • BKPF：会計伝票のヘッダ（見出し：日付・会社など）
  • BSEG：会計伝票の明細（中身の行：金額・科目）
  • T001：会社コードのマスタ（会社の一覧）
  • T003T：伝票タイプの名称（コードの読み仮名表）
Aくん：ヘッダ＝BKPF、明細＝BSEG。第2章の「ヘッダと明細」がそのまま表になっているんですね。

条件をつけて、内部テーブルへ受け取る

選択画面で受け取った条件を WHERE に渡し、結果を内部テーブルに入れます。

SELECT belnr budat bukrs
  FROM bkpf
  INTO TABLE lt_bkpf
  WHERE bukrs IN s_bukrs
    AND budat IN s_budat.
先生：INTO TABLE は「複数行をまとめて棚（内部テーブル）に入れる」という意味。1件だけなら SELECT SINGLE を使います。

取得できたかを SY-SUBRC で判定

SELECT の直後、システムは SY-SUBRC という変数に結果を入れます。0なら成功（取れた）、0以外なら「該当なし」です。これを見て処理を分けます。

SELECT ... INTO TABLE lt_bkpf WHERE ...

IF sy-subrc = 0.
  " 取れた → 続けて処理
ELSE.
  MESSAGE '該当する伝票がありません' TYPE 'I'.
ENDIF.
つまずき：取れなかったのに、そのまま後続処理に進んで空っぽの結果を出してしまう。→ 必ず SY-SUBRC を確認しましょう。

図で見る：条件→抽出→件数判定→分岐

flowchart TD
  A[選択画面の条件] --> B[SELECT で抽出]
  B --> C{SY-SUBRC = 0?}
  C -->|はい 取れた| D[後続処理へ]
  C -->|いいえ なし| E[メッセージを出す]
この章のABAPキーワード：SELECT / SELECT SINGLE / INTO TABLE / WHERE / SY-SUBRC / IF / CASE / MESSAGE。

2人の理解ポイント

Aくん：SY-SUBRC は“戻り値”ですね。0=正常という規約だと思えば腹落ちします。
Bちゃん：「取れたか確認してから次へ」。お弁当を買えたか確かめてからレジを離れる、みたいなことですね。
先生：その感覚で大丈夫。「取得 → 確認 → 分岐」は、登録処理でも繰り返し出てくる超基本です。
